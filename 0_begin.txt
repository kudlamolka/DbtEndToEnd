*** DBT ***

In DBT there are 2 types DBT Cloud (Paid - UI)) and DBT Core (Open source - CLI)

We are using the Core, so there we need to do some setup.

First create a Python virtual environment. 

%
python -m venv dbte2e
dbte2e/Scripts/activate
%

Then we move on to install the required packages

%
pip install dbt-snowflake==1.9.0
%

We need to create a root folder for dbt (.dbt), so the below commands are run

%
mkdir ~/.dbt
%

Then we have to create a DBT Project folder using the dbt init <project name>
%
dbt init netflix
%

Since I am using Snowflake, it first asked for the database, and I said I want the snowflake,
Then it asked details related to Snowflake account
1) Account identifier
2) Username
3) Password
4) Role
5) Warehouse
6) Database
7) Schema
8) Thread

All these are same details that was used, when we created the dbt user in snowflake.

With this, the profiles.yml would be created in the .dbt folder

*** DBT Model ***

It is a simple sql file, that is used to create the models.

We will have RAW Schema, where we will have the data that we get from the source as it is.
We create our src tables, on which we will be reference now onwards

RAW (Actual Tables loaded manually) -> RAW (Source Views in Staging Layer)

Once we prepare the queries to prepare the source views, we ran

%
dbt run
%

This created the views in the snowflake in the RAW Schema itself.

Q : Why was view created?
A : This is because in the dbt_project.yml file, all the models are configured to create a view
    +materialized: view

The table, view and materialized view is something straight forward.

There is something called 'ephemeral' materialization, which is a type of materialization that is used to create a temporary table, which is used only within thescope of the dbt project.
There is also something called 'incremental' materialization, which detects the changed inserted or updated records since last run.

Once the data is there is staging, we should be creating dimension tables and fact tables.
We will be loading the incremental data.

We need actual tables to be created here. So, in the dbt_project.yml we will be adding a folder inside project, called 'dim'
Here the materialized will be 'table'

Did you notice, that we are creating all the tables in the same schema in Snowflake, i.e., 'RAW'.
But, it's recommended to have different schema for RAW data (loaded manually), Staging and Dimension.

For this, we need to update the profiles.yml

I changed the schema from 'RAW' to 'DEV' in the profiles.yml

We will be creating the Source Views and Dimensions in DEV, instead of 'RAW'. 
Now, we also need to drop these tables from the RAW schema.

DROP TABLE DIM_MOVIES;
DROP VIEW SRC_GENOME_SCORES;
DROP VIEW SRC_GENOME_TAGS;
DROP VIEW SRC_LINKS;
DROP VIEW SRC_MOVIES;
DROP VIEW SRC_RATINGS;
DROP VIEW SRC_TAGS;

Then ran the 'dbt run' to create the src views and dim tables

Then we created 2 more dimensions, 

One is dim_users, were we got the distinct users from src_tags and src_ratings.
The other one is the dim_genome_tags, where we simple capitalize the first alpha character and trimmed the string.

We also created a new fact table, fct_genome_scores, which is a fact table for the genome scores.
and added the new folder in the dbt_project.yml to create it as table

If we want to run only a single model, then we have to run the below commands

%
dbt run --model fct_genome_scores
%

NOTE : If we create the wrong type of materization, then changing it in the dbt_project.yml and rerunning the model 
will apply the change in the target.
